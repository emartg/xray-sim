## [Unreleased]

### Added

- Top-level CMake project (CMake 3.26, C++20) that builds the Engine and the core library of gVirtualXRay as subdirectories, with a `vcpkg.json` manifest pinned to the Engine's baseline, and CMake presets for Ninja with MSVC, Visual Studio 2022 and 2026, MinGW Makefiles with GCC (Windows), and Ninja with GCC or Clang (Linux), adapted from the Engine's.
- `XRSim`, a minimal application on top of the Engine (a window with a placeholder panel) with the `--frames N` command-line option, and the tests `XRSim_Smoke_Test` and `XRSim_Invalid_Argument_Test`.
- GitHub Actions CI: formatting check with clang-format 23.1.1, Linux builds (GCC Debug and Clang Release, with the tests under a virtual display), and Windows builds (MSVC and MinGW, with a vcpkg binary cache).
- gVirtualXRay, as a Git submodule of the fork, built as its core library alone (option `XRSIM_BUILD_XRAY`, off by default with MSVC), with the system packages on Linux and vcpkg packages on Windows (triplets `x64-windows-xray` and `x64-mingw-dynamic-xray`, which build GLEW as a static library, as the fork requires).
- `XRSim_Xray`, the library that adapts gVirtualXRay to the simulator (it links the library privately and does not expose its headers), with the class `Gvxr_Adapter` and the test `Gvxr_Adapter_Test`.
- Build instructions, the credits of the third-party libraries and resources (`docs/sources.md`), and the formatting configuration of the Engine (`.clang-format` and `.editorconfig`).
- The adapter computes X-ray images: `Gvxr_Adapter` owns the X-ray renderer, the beam, the detector, and the meshes, and computes the image of the meshes on the OpenGL context of the Engine's window, inside the Engine's frame. It saves the state of OpenGL, sets the defaults that the library relies on, and restores the state after each call, and its interface uses plain types (`Xray_Types.h`), without headers of the library or of the Engine. A workaround is needed to register the current context with the library, which cannot adopt an existing one (it goes away when the library provides a function for it).
- `--xray-self-test` option and `XRSim_Xray_Self_Test`: in the first frame, the simulator computes the X-ray image of a cube of water of 10 cm with a beam of 80 keV, and checks that the transmission is the one of the Beer-Lambert law (0.1593, within 3 percent) and that the state of OpenGL is unchanged.
- The scene library `XRSim_Scene`: a cube, a sphere, and a cylinder as closed surfaces with outward triangles, a table of materials (water, aluminium, iron, and bone), and the `Scene` class, with a default scene and the X-ray meshes of its objects in millimetres (the unit of a scene is the centimetre), and its test `Scene_Test`, which also runs in the Windows jobs of the CI.
- The Engine draws the default scene with its forward rendering (a camera, a directional light, and a node for each object, built by `Scene_Builder`), and a `Scene` window lists the objects.
- The X-ray image of the scene, next to the 3D view: `Xray_View` gives the meshes of the scene to gVirtualXRay once, computes the image of a point source and a flat detector (256 by 128 pixels of 2 mm, 80 keV) when the first frame is drawn and when the user presses the Recompute button, and shows it in an `X-ray` window. The `Single X-ray view` switch shows the image as the background of the whole window instead, and the scale (linear or logarithmic) and the negative can be chosen.
- The display library `XRSim_Display`: the conversion of an X-ray image to grey values, relative to the unattenuated beam (linear or logarithmic, optionally negative), with its test `Xray_Display_Test`.
- Controls of the X-ray setup in an `X-ray setup` window: the energy of the beam (20 to 150 keV), the distance of the source and of the detector to the scene, the size of a pixel, and the size of the detector in pixels. The image is computed again when a value changes (the option `Recompute on change`, with an `Apply` button when it is off, and a `Reset` button), and the window shows the magnification and the size of the detector. The setup is the new class `Xray_Setup` of the scene library, which converts the distances to the millimetres of the X-ray library and keeps every value within its limits (for example, the source cannot be inside of the scene), with its test `Xray_Setup_Test`.
- `--xray-view-test` option and `XRSim_Xray_View_Test`: in the first frame, the simulator checks that the corners of the X-ray image of the scene are not attenuated, that the beam is attenuated where each object projects, and that the iron sphere attenuates more than the water sphere. It also changes the setup, and checks that a lower energy attenuates more and that another geometry and detector give a valid image of the new size.
- The pin guard: CMake stops at configure time when `engine/` or `gvirtual-xray/` (when the X-ray part is on) is not at the commit that the repository records for it. The index is compared, so a new pin can be tried with `git add` before it is committed. The message names the folder, both commits, and the two ways out (`git submodule update <folder>`, or `git add <folder>` and a commit); the option `XRSIM_ALLOW_UNPINNED_SUBMODULES` turns the stop into a warning; and the check is skipped, with a status message, when Git is not available, the sources are not a Git checkout, or a submodule was not fetched. Its test, `Submodule_Pin_Guard_Test`, creates small Git repositories and runs the guard on them.
- Timers around the stages of the X-ray image: the adapter measures its state guard, its initialisation (the loading of the OpenGL functions and the renderer apart), the addition of the meshes, the computation (until the GPU has finished), and the read-back, and Xray_View measures the destruction of the previous adapter, the meshes of the scene, the mirror, the grey conversion, and the upload of the texture. Every change of the X-ray setup prints the times ([INFO::XRAY_VIEW::apply_setup] ...), and the X-ray setup window shows them with the number of images computed in the last five seconds and the frames per second. The --xray-self-test option checks that the times are valid.

### Changed

- The README describes the current state of the prototype (the scene drawn by the engine, the X-ray image of the scene, the controls of the X-ray setup, the pin check, and what comes next) and the structure of `src/`, `tests/`, and `cmake/`.
- The pointer of the gVirtualXRay submodule moves to the latest commit of the fork, which has: the function `Context::adoptCurrentContext()`, to use the OpenGL context of the application (the simulator still uses its workaround, until a later change); the include of its MinGW fix header only with MinGW, which the MSVC build needs; the coverage flags of its Debug build as an option that is off by default; and changes of its own continuous integration. The Engine stays at v0.9.0.

### Fixed

- The Windows jobs of the CI use their vcpkg binary cache when GitHub moves a job to another build of the runner image: the CI triplets leave the compiler out of the ABI hash of the packages.
- The Windows jobs of the CI ran only some of the unit tests: they also run `Xray_Setup_Test`, `Xray_Display_Test`, and `Submodule_Pin_Guard_Test` now.
